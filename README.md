# Atlas-Lite

**Windows 桌面自動化(RPA)+ Python 腳本流程引擎。零 LLM 也能完整運作。**

從 [Atlas](../Atlas) 抽取而來,只保留四種節點:

| 節點 | 做什麼 |
|---|---|
| **Python 腳本** | 執行你自己的 `.py` 或任何命令,步驟間可傳結構化資料 |
| **桌面自動化** | 錄製滑鼠鍵盤 → 回放。UIA / CV 錨點比對 / OCR 三層定位 |
| **條件分支** | IF / Switch,用 Jinja2 表達式求值,不是 `eval`、也不是 LLM |
| **人工確認** | 暫停等你點頭,可推播到 Telegram 遠端決定 |

外加:排程、Webhook 觸發、資料夾監看觸發、Secrets Vault。

### 步驟之間怎麼傳資料

三種方式,腳本不用學任何 API:

```python
# 1. 寫 _step_export.json 到 cwd → 下游用 {{ steps.抓資料.output.rows }}
json.dump({"rows": 150}, open("_step_export.json", "w"))

# 2. output.path 指向 .json → 裡面的純量欄位自動開放給下游引用
json.dump({"rows": 150, "status": "ok"}, open("result.json", "w"))
```

```yaml
# 3. output.json_schema —— 唯一的輸出驗證機制,0 成本、錯在哪一欄講得清楚
output:
  path: result.json
  json_schema: { type: object, required: [rows], properties: { rows: { type: integer } } }
```

## 跟 Atlas 的關係

Atlas-Lite 是**獨立專案**,不是 Atlas 的模組或 submodule:

- 獨立 git repo、獨立 venv、獨立資料目錄
- 不 import Atlas 的任何程式碼
- 程式碼是**複製過來改**的,兩邊各自演進

檔案若源自 Atlas,檔頭會註明來源,方便日後互相回補修正。

| | Atlas | **Atlas-Lite** |
|---|---|---|
| 定位 | AI 工作流編排(LLM 為核心) | **純自動化執行引擎** |
| LLM | 必要 | **完全不需要** |
| 沙盒(WSL+Docker) | skill 節點需要 | **不需要** |
| 後端埠 | 8014 | 8020 |
| 前端埠 | 3012 | 3020 |

---

## 為什麼「無 LLM」是可行的

抽取前做過完整依賴盤查,結論:

- **純腳本執行路徑零 LLM** —— 從 API 到 `subprocess` 中間沒有任何模型呼叫
- **桌面自動化的 15 種動作全部零 LLM** —— 點擊 / 輸入 / 熱鍵 / 拖曳 / 捲動 / 等待 / 斷言 / 條件分支 / 重試迴圈
- **腳本節點本來就在 host 執行**,且刻意與後端 venv 脫鉤,沙盒只服務 LLM 生成的程式碼

LLM 在原專案裡負責的是「**產生**工作流」與「**看圖判斷**」,不是「執行」。Atlas-Lite 把執行的部分完整保留。

## 系統需求

| 項目 | 版本 | 必要性 |
|---|---|---|
| Windows | 10 / 11 | 必要(桌面自動化只支援 Windows) |
| Python | **3.11 ~ 3.13** | 必要 |
| Node.js | 18+ | 必要(前端) |
| NVIDIA GPU(6GB VRAM 以上) | — | **選用**,只有要用 GUI 定位模型才需要 |

> ⚠ **不要用 Python 3.14。** pydantic 2.9.2 還沒有 3.14 的 wheel,pip 會改成用 Rust
> 從原始碼編 `pydantic-core`,在沒裝 MSVC build tools 的機器上會噴一整面 cargo 錯誤
> ——看起來像專案壞了,其實只是 Python 版本太新。
> `launch.bat` 會自動挑 3.13 → 3.12 → 3.11,所以照它跑就不會踩到;
> 只有手動建 venv 才需要注意。

**不需要** WSL2、Docker、任何 LLM API Key。

### 關於「不需要 API Key」

這不是「先不填也能跑、之後要填」的意思 —— Atlas-Lite **沒有任何呼叫雲端模型的
程式碼**,`.env` 裡也沒有 API key 欄位(唯一的憑證是選填的 Telegram bot token)。

唯一的 AI 元件是**地端** GUI 定位模型,它靠安裝外掛而不是靠金鑰,截圖不出網路。
從 Atlas 匯入的工作流若帶了雲端 VLM 設定(`vlm_mode: description` / `anchor_pick`
/ `vlm_check` 動作),執行時會**明確報錯並告訴你怎麼改**,不會靜默改用別的方式點下去。

## 選用:GUI 定位模型(地端 VLM)

桌面自動化預設用**錨點圖 + CV 比對**找按鈕。錨點會因為主題色改變、視窗縮放、對方軟體改版而失效。這個模型讓你改用**一句話描述**定位:

```yaml
- type: click_image
  vlm_mode: grounding
  vlm_prompt: "工具列上的排序按鈕"
```

模型只回答「**在哪裡**」,動作種類仍由 YAML 決定;失敗自動退回 CV 比對。

**全程地端推論,不呼叫外部 API、截圖不出網路。**

### 硬體與效能(2026-08-06 Windows host 實測)

| 可用 VRAM | 自動採用 | 峰值佔用 | 定位誤差中位數 | 每次推論 |
|---|---|---|---|---|
| 12GB 以上 | fp16 | 9.65 GB | 3.0 px | 5.1 秒 |
| 6GB 以上 | int4 | 3.68 GB | 3.6 px | 6.0 秒 |
| 低於 6GB | 不啟用 | — | — | — |

精度由系統依可用記憶體自動選,使用者不需設定。量化幾乎不影響精度(3.0 vs 3.6 px)。

**安裝**:

```cmd
plugins\vlm_grounding\setup.bat
```

需要 8.9GB 下載、8.3GB 磁碟、約 2.9GB 的 CUDA PyTorch。僅支援 NVIDIA。

### 已知限制

以下都是實測結果,不是推測。

**① 它不會承認找不到目標**
問畫面上沒有的東西(例:「紫色獨角獸圖示」),它會自信地指一個最像的位置。
系統拿錄製的錨點圖做局部比對擋掉 —— 實測那次幻覺拿到 0.447 分,門檻 0.55 擋下。
但那是粗篩:擋得住「指到畫面另一區」,擋不住「指到隔壁長得很像的按鈕」。

**② 它不會靠文字辨識身分**
這是最容易誤解的一點。實測「標題是『XXX』的那個視窗的關閉按鈕」:

| 描述方式 | 結果 |
|---|---|
| 「標題是 XXX 的那個視窗的關閉鈕」 | **0/2 全錯**,兩個答案還互換 |
| 「畫面**左上方**那個視窗的關閉鈕」 | ✅ 誤差 7px |
| 「畫面**右下方**那個視窗的關閉鈕」 | ✅ 誤差 3px |

它找的是「看起來像關閉鈕的東西」,不會讀標題來分辨是哪個視窗。
**要指定操作哪一個視窗,用 UIA(`uia_window` / `uia_close_window`),不要用 VLM。**

**③ 描述不要用否定句**
「不是視窗關閉鈕的那個 X」—— 修飾語會被忽略而點錯,改用正面且獨特的特徵。

**④ 不要拿它讀畫面上的文字**
長字串會編造。讀值請用 OCR 或直接回資料源。

**⑤ 破壞性動作後面加 `assert_image` 驗證**
不要單獨依賴定位結果。

### 什麼時候該用它

它的長處是「在畫面上找一個**看得出來**的東西」。所以:

| 目標 | 建議 |
|---|---|
| 視窗、選單、一般控制項 | **UIA**(0px、0.2 秒,實測抓取率 92%) |
| 有穩定錨點圖的按鈕 | **CV 錨點比對** |
| Canvas 畫的、遊戲介面、每次配色都不同的網頁元件 | **地端定位模型** |

換句話說:它是**前兩者都失效時**的備案,不是首選。

## 快速開始

```cmd
launch.bat
```

首次執行會自動建立 venv、安裝相依、啟動前後端。開 http://localhost:3020。

無頭機器(或用排程 / Webhook / Telegram 驅動)只要後端:

```cmd
launch.bat --no-frontend
```

不填任何設定就能用 —— 沒有 API 金鑰要準備。`.env` 只有 Telegram 與路徑,全部選填。

## 從 Atlas 匯入既有工作流

匯出的 zip 直接拖進側邊欄即可,但兩件事要知道:

- **用到 AI 節點的工作流會被明確擋下**,錯誤訊息會指出是哪一步、哪種節點。
  這是刻意的 —— 靜默丟掉會讓一個 AI 技能節點退化成「空指令的腳本節點」,
  跑起來 exit 0 卻什麼都沒做,比載入失敗糟糕得多。
- **錨點圖不會跟著進來**。它們動輒幾十 MB,而且換一台機器解析度不同本來就要重錄。

## 安全性

這個後端會在你的電腦上**執行任意腳本、操作你的桌面**。以下不是形式條款:

- API **沒有認證**。預設只綁 `127.0.0.1`,
  **綁 `0.0.0.0` 等於把整台機器交給區網上任何人**。
- **Webhook token 就是憑證** —— 外流等同把執行權交出去。只有你按「建立」才會有,
  隨時可以重新產生(舊的立刻失效)。
- **Telegram 遠端遙控預設關閉**。開了之後,設定裡那個 chat 可以直接在這台機器上
  啟動工作流。只有你自己會用手機遙控時才開。
- **安裝套件一定要經過你按鈕授權**。步驟因為 `ModuleNotFoundError` 失敗時,
  系統會問你,不會自己裝。
- 被自動化的應用程式密碼請放 **Secrets Vault**(設定頁),用 `{{ secrets.名稱 }}` 引用,
  不要寫進 YAML。誠實說明:金鑰檔就在同一台機器上(`data/.vault_key`),
  這擋的是「DB 或匯出包外流時裡面沒有明文」,不是擋拿得到你電腦的人。
